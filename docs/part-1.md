# Fixing Part 1 — Foundation cleanup and contract correction

This is the first of three **fixing parts**, not completion of Product Phase 1.
The original goal remains two-way Indian Sign Language communication, Mode 1
first, with the 12-gloss bootstrap vocabulary and separate frontend/backend/ML
layers. Product phases remain in `docs/phases/`.

## Acceptance criteria

- Preserve the original product vision while correcting completion claims.
- Use the canonical shared vocabulary and validated, consistent message formats.
- Report unavailable AI services without fabricated successful outputs.
- Bound inputs and uploads, isolate or disable WebSockets, enforce explicit
  origins/hosts, safe errors, production debug off, and security headers.
- Preserve each original security/architecture requirement and its evidence.
- Remove generated bytecode from Git tracking; preserve source and local data.
- Test changes, inspect diffs, and deliver coherent commits to `Swayam`.
- Run Duck before advancing to Fixing Part 2.

## Delivery progress

### Canonical vocabulary loading

The backend now reads `items` from the shared vocabulary, validates entries,
supports BOM-bearing UTF-8, and applies optional context allowlists. Missing or
invalid vocabulary does not silently enable a different hard-coded dictionary.
Keyword aliases are still filtered against the active vocabulary.

The existing text-to-gloss query endpoint accepts an optional context. REST
message/envelope migration is still pending in this checkpoint.

### Verification environment

An ignored backend `.venv` uses the original declared requirements for baseline
verification. Baseline: 27 backend tests passed; 3 frontend tests passed after
`npm ci --ignore-scripts --no-audit --no-fund`. No application build was run.
The first Python audit found advisories in `python-multipart==0.0.20` and
`pytest==8.4.2`; dependency corrections and a transitive audit remain open.

Other saved Part 1 edits are being reviewed and delivered in subsequent
checkpoints. This file does not mark the entire part complete.

### Honest optional-service status and safe error baseline

Whisper, sign inference, and TTS report disabled (501) or enabled but unavailable
(503), never fabricated successful output. Health/capabilities distinguish
configuration from availability. Boolean/numeric settings are validated and
production debug is forced off. HTTP/validation/unhandled errors use a safe error
object with the legacy `detail` field retained during migration. Request IDs and
success-envelope alignment follow in the contract checkpoint.

### Dependency audit corrections

The transitive baseline audit also flagged Starlette 0.48.0 and the virtual
environment's pip 25.0.1. FastAPI must move with Starlette because the old
FastAPI pin disallows patched Starlette versions. Runtime pins now target
FastAPI 0.142.2, Starlette 1.7.0, and python-multipart 0.0.31. Test tooling uses
pytest 9.1.1. HTTPX is a test dependency, not an unused runtime dependency.
The virtual environment's pip is updated independently; it is not an app API.
After these corrections, all 31 backend tests passed, `pip check` passed and
the complete installed-environment `pip-audit` reported no known vulnerabilities.
`constraints.txt` records the audited Windows/Python 3.12 dependency resolution.

### Canonical message validation

Conversation, speech-result, and sign-prediction models now serialize against
the shared v1 JSON schemas. Inputs reject invalid sources, unknown glosses,
oversized text, unexpected fields, incorrect frame dimensions, and nonfinite
landmarks. Conversation IDs/timestamps support the documented input migration
in ADR-009. These checks do not implement model inference or browser capture.

### REST integration and frontend compatibility

All REST responses now use the canonical success/error envelope with request IDs.
The frontend adapter unwraps data, handles safe errors, bounds request time, and
uses JSON language requests. Backend integration tests validate actual responses
against shared schemas and check invalid inputs. The frontend vocabulary now
comes from the same shared JSON; transcript keys and JSDoc follow canonical IDs.
Wire details and bounded legacy inputs are in `docs/api/current-contract.md`.

### Bounded HTTP and denied private access

The five previous checkpoints were verified on remote `Swayam` through
`40e3d89`. The interrupted HTTP edit initially failed 20 tests: old test hosts,
old socket expectations, and a newly required production origin configuration.
Tests now use actual allowed hosts and verify the stricter boundary.

Exact hosts/origins, finite body/peer/concurrency limits, cooperative timeouts,
safe error headers, metadata-only request logging, HTTPS production checks, and
deny-by-default private-route dependencies are implemented. `/ws` is closed for
Mode 1; no configuration flag bypasses that decision. No account system is
claimed. API security does not substitute for frontend viewport/accessibility
checks or a production deployment review.

Verification: 92 backend tests pass, including chunked overflow, slow body,
concurrent request saturation/recovery, permission/ownership denial, CORS,
production TLS, and safe unexpected errors. Audio content validation and
removal of unused broadcast helpers follow in the next checkpoint.
