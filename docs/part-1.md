# Fixing Part 1 — Foundation cleanup and contract correction

This is the first of three **fixing parts**, not completion of Product Phase 1.
The original goal remains two-way Indian Sign Language communication, Mode 1
first, with the 12-gloss bootstrap vocabulary and separate frontend/backend/ML
layers. Product phases remain in `docs/phases/`.

## Acceptance criteria

- Preserve the original product vision while correcting completion claims.
- Use the canonical shared vocabulary and validated, consistent message formats.
- Report unavailable AI services without fabricated successful outputs.
- Bound inputs and uploads, isolate or disable WebSockets, enforce explicit
  origins/hosts, safe errors, production debug off, and security headers.
- Preserve each original security/architecture requirement and its evidence.
- Remove generated bytecode from Git tracking; preserve source and local data.
- Test changes, inspect diffs, and deliver coherent commits to `Swayam`.
- Run Duck before advancing to Fixing Part 2.

## Delivery progress

### Canonical vocabulary loading

The backend now reads `items` from the shared vocabulary, validates entries,
supports BOM-bearing UTF-8, and applies optional context allowlists. Missing or
invalid vocabulary does not silently enable a different hard-coded dictionary.
Keyword aliases are still filtered against the active vocabulary.

The existing text-to-gloss query endpoint accepts an optional context. REST
message/envelope migration is still pending in this checkpoint.

### Verification environment

An ignored backend `.venv` uses the original declared requirements for baseline
verification. Baseline: 27 backend tests passed; 3 frontend tests passed after
`npm ci --ignore-scripts --no-audit --no-fund`. No application build was run.
The first Python audit found advisories in `python-multipart==0.0.20` and
`pytest==8.4.2`; dependency corrections and a transitive audit remain open.

Other saved Part 1 edits are being reviewed and delivered in subsequent
checkpoints. This file does not mark the entire part complete.

### Honest optional-service status and safe error baseline

Whisper, sign inference, and TTS report disabled (501) or enabled but unavailable
(503), never fabricated successful output. Health/capabilities distinguish
configuration from availability. Boolean/numeric settings are validated and
production debug is forced off. HTTP/validation/unhandled errors use a safe error
object with the legacy `detail` field retained during migration. Request IDs and
success-envelope alignment follow in the contract checkpoint.
